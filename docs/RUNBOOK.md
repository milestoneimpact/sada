# دليلُ الاسترجاع — ما يُفعل يومَ يقع ما لا يُراد

> D-321 · 2026-11-12. **كلُّ أمرٍ هنا يُنسَخ كما هو**، والبيئةُ فيه staging (`sada2.basserh.com`، القاعدة `sada-staging`، العامل
> `sada-api-staging`) لأنّها التي تحمل حساباتك الحقيقيّة (D-271). وللإنتاج (`sada.basserh.com`) بُدّل `staging` بـ`production`
> و`sada-staging` بـ`sada` و`sada-backup-staging` بـ`sada-backup` — **ولا يُخلَط بينهما في أمرٍ واحد**.
> والأوامرُ من جذر المستودع على حاسوبك بعد `npx wrangler login` بحساب Cloudflare نفسِه؛ **ولا يحتاج شيءٌ منها دقائقَ GitHub** (M-23).
> وكلُّ ما يقع يُكتب حادثةً في [`INCIDENTS.md`](INCIDENTS.md) بقالبها، والأهدافُ وهامشُها في [`SLO.md`](SLO.md).

## ما يُسترجَع وإلى أين

| ما وقع | الطريق | يُفقَد (RPO) | الزمن (RTO) |
|---|---|---|---|
| نشرٌ سيّئ (الشيفرة) | §١ · `wrangler rollback` | لا شيء | دقائق — **لم يُقَس** |
| ترحيلٌ سيّئ (المخطَّط أو الصفوف) | §٢ · Time Travel إلى علامة ما قبل الترحيل | ما كُتب بعد العلامة | دقائق — **لم يُقَس** |
| فقدُ بياناتٍ أقدمُ من ثلاثين يومًا، أو القاعدةُ حُذفت | §٣ · النسخةُ الأسبوعيّة من R2 | حتّى سبعة أيّام | **لم يُقَس — M-52** |
| `TOKEN_ENC_KEY` ضاع | §٤ | كلُّ عمودٍ مشفَّر | ساعات (إعادةُ ربط) |
| المالكُ لا يدخل | §٥ | لا شيء | دقائق |

**آخرُ تمرين**: التمرينُ الآليُّ في كلّ `npm run ci` (نسخةٌ مصنوعةٌ بـ38 جدولًا تُسترجَع في نحو ‏150ms، `npm run drill`).
**والتمرينُ الحقيقيُّ لم يُجرَ بعد** (M-52)؛ وزمنُه يُكتب هنا حين يُجرى.

## §١ · نشرٌ سيّئ — `wrangler rollback`

**متى**: «التحقّق من النشر» في GitHub Actions أحمر، أو اللوحةُ تردّ 500، أو `/pulse` ‏503 بعد نشرٍ مباشرةً.

1. أوقف الجديد قبل أن يُعاد: لا تدمج شيئًا في `main` حتّى يُصلَح — كلُّ دمجٍ ينشر.
2. انظر النسخ: `npx wrangler deployments list --env staging` — الأحدثُ أوّلًا، و«Message» فيه معرّفُ الالتزام (D-319).
3. ارجع إلى ما قبلها: `npx wrangler rollback --env staging -m "rollback: <السبب>"` (إلى النسخة السابقة)، أو
   `npx wrangler rollback <VERSION_ID> --env staging -m "rollback: <السبب>"` لنسخةٍ بعينها.
   **أو من اللوحة بلا طرفيّة**: Workers & Pages ← `sada-api-staging` ← **Deployments** ← النسخةُ السليمة ← **⋯** ← **Rollback**.
4. **ثمّ اعكس الالتزام** في طلب دمج (`git revert <sha>`)، وإلّا أعاد الدمجُ التالي نشرَه.

**التحقّق**: `curl -s https://sada2.basserh.com/ready` يقول `"version"` النسخةَ التي رجعت إليها و`"database":"ok"`، و
`curl -s -o /dev/null -w '%{http_code}\n' https://sada2.basserh.com/pulse` يردّ ‏200، واللوحةُ تفتح.

**وما لا يرجع به**: الترحيلُ (القاعدة) والأسرار. والترحيلاتُ تُضاف ولا تُسقط (D-316)، فالشيفرةُ القديمة تقرأ مخطَّطًا أحدث؛ وإن كان الترحيلُ
نفسُه هو العطل فـ§٢ **بعد** هذا القسم لا قبله.

## §٢ · ترحيلٌ سيّئ — Time Travel إلى علامة ما قبل الترحيل

**متى**: ترحيلٌ محا صفوفًا أو أفسدها أو كسر قيدًا، و**في الثلاثين يومًا** (سبعةٌ على الخطّة المجّانيّة).

1. **العلامة**: GitHub ← Actions ← تشغيلُ **deploy** الذي حمل الترحيل ← **Summary** ← «علامةُ الاسترجاع قبل الترحيل»: فيه العلامةُ ووقتُها
   والأمرُ كاملًا (D-321). وإن لم يكن (نشرٌ قبل D-321)، فاشتقّها من وقتٍ قبله:
   `npx wrangler d1 time-travel info sada-staging --env staging --timestamp=<وقتٌ UTC قبل الترحيل، 2026-11-12T03:00:00Z>`
2. **أوقف النشر**: اللوحة ← **الضبط** ← **الإنفاق والحدود** ← **الإيقاف المؤقّت** ← شغّله.
3. **ارجع بالعامل أوّلًا** (§١) إلى النسخة التي سبقت الترحيل: الشيفرةُ الجديدة تقرأ ما لن يبقى بعد الاسترجاع.
4. **احفظ ما نُشر بعد العلامة** — الاسترجاعُ يمحو صفوفَ نجاحه، فيعود المنشورُ «مجدولًا» ويُنشَر ثانيةً:
   `npx wrangler d1 execute sada-staging --env staging --remote --json --command "SELECT pa.post_id, p.platform, pa.platform_post_id, pa.at FROM publish_attempts pa JOIN posts p ON p.id = pa.post_id WHERE pa.status = 'succeeded' AND pa.at >= '<وقتُ العلامة بصيغة 2026-11-12 03:00:00>'" > published-after.json`
5. **استرجع**: `npx wrangler d1 time-travel restore sada-staging --env staging --bookmark=<العلامة>` ← **y**.
   **واحفظ العلامةَ التي يطبعها للتراجع** («To undo this operation…»).
6. **صالِح ما نُشر بعدها**: لكلّ `post_id` في الملفّ:
   `npx wrangler d1 execute sada-staging --env staging --remote --command "UPDATE posts SET status = 'published' WHERE id IN ('<id1>', '<id2>') AND status IN ('queued', 'approved')"`
7. أوقف النشرَ ثانيةً من اللوحة (الاسترجاعُ أعاد الإعدادَ كما كان)، ثمّ **اعكس الترحيلَ في طلب دمج**: الاسترجاعُ أعاد `d1_migrations` إلى ما
   قبله، فالنشرُ التالي يطبّقه ثانيةً إن بقي. وارفع الإيقاف بعد أن يُنشَر الإصلاح.

**التحقّق**: `npx wrangler d1 execute sada-staging --env staging --remote --command "SELECT name FROM d1_migrations ORDER BY id DESC LIMIT 3"`
يقول آخرَ ترحيلٍ قبل السيّئ؛ و`SELECT count(*) AS n FROM posts` (وما محاه الترحيلُ من جداول) يعود إلى عدده؛ و`/ready` ‏`"database":"ok"`.

**يُفقَد**: كلُّ ما كُتب بعد العلامة (مسوّداتٌ واعتماداتٌ وقياسات) — والخطوة ٤ تحفظ أخطرَه: ما خرج إلى المنصّات.

## §٣ · فقدُ بيانات — النسخةُ الأسبوعيّة من R2

**متى**: ما فات Time Travel (أقدمُ من ثلاثين يومًا، أو عطبٌ اكتُشف متأخّرًا)، أو القاعدةُ أو الحسابُ حُذف. **ويلزم** `TOKEN_ENC_KEY`
من خزانتك (M-51) ومستودعٌ مسحوبٌ بـ`npm ci` وNode ≥ ‏22.13.

**ما النسخة**: كلَّ سبعة أيّامٍ تأخذ الدورةُ اليوميّة (03:03 UTC) نسخةً من كلّ جداول D1 في معاملةٍ واحدة إلى `sada-backup-staging`
(`snapshots/<الوقت>-<kid>.sada`)، مشفّرةً بـ AES-256-GCM بمفتاحٍ مشتقٍّ بـ HKDF من `TOKEN_ENC_KEY` (`info = backup-v1`)، والأعمدةُ
المشفّرةُ فيها كما هي. وآخرُ ثمانٍ تبقى (شهران)، وقفلُ الدلو يمنع حذفَ ما دون ثلاثين يومًا. والصيغةُ في `src/lib/ops/snapshot.ts`.

1. **نزّل النسخة**: R2 ← `sada-backup-staging` ← **Objects** ← الأحدثُ قبل الفقد ← **Download**، أو
   `npx wrangler r2 object get sada-backup-staging/snapshots/<الاسم>.sada --remote --file snap.sada`
2. **المفتاح**: `read -rs TOKEN_ENC_KEY && export TOKEN_ENC_KEY` ← الصقه من الخزانة (لا يظهر، ولا يبقى في سجلّ الطرفيّة).
3. **افتحها وافحصها**: `time npm run restore -- snap.sada --out restored.sqlite --sql restore-data.sql` — يبني قاعدةً بترحيلاتها، ويعدّ
   كلَّ جدول، ويفحص المفاتيحَ الأجنبيّة و`integrity_check`، ثمّ يرحّلها إلى مخطَّط اليوم ويكتب صفوفَها جملًا في `restore-data.sql`.
4. **إلى D1**:
   - **القاعدةُ قائمة** (صفوفٌ فسدت): أوقف النشر (§٢ · ٢)، وخذ علامةً للتراجع (`npx wrangler d1 time-travel info sada-staging --env staging`)،
     ثمّ `npx wrangler d1 execute sada-staging --env staging --remote --file restore-data.sql` — **يمحو كلَّ جدولٍ ويكتب صفوفَ النسخة**.
   - **القاعدةُ حُذفت**: `npx wrangler d1 create sada-staging` ← ضع المعرّفَ الجديد في `wrangler.toml` (`[[env.staging.d1_databases]]`) في
     طلب دمج ← `npm run migrate:staging` ← `npx wrangler d1 execute sada-staging --env staging --remote --file restore-data.sql` ← انشر.
5. `unset TOKEN_ENC_KEY && rm snap.sada restored.sqlite restore-data.sql` — الملفّان الأخيران فيهما صفوفُ القاعدة.

**التحقّق**: أعدادُ الجداول في D1 (`SELECT count(*) AS n FROM <الجدول>`) هي ما طبعه التمرين؛ و`/ready` ‏`"database":"ok"`؛ و«الحسابات»
في اللوحة «متّصلة» لا «تحتاج إعادة ربط» (الرموزُ فُكّت بالمفتاح نفسِه)؛ و«صحّة صدى» تقرأ.

**يُفقَد**: ما بعد آخر نسخة — حتّى سبعة أيّام. ونسخةٌ أقدمُ من التدوير تحتاج المفتاحَ السابق: `export TOKEN_ENC_KEY_PREV` بقيمته.

## §٤ · `TOKEN_ENC_KEY` ضاع

**ما يحمله**: كلُّ إذنٍ مربوط (`tokens`)، وكلُّ مفتاح خدمةٍ في الخزانة (`providers`)، وأسرارُ تطبيقات OAuth (`oauth_apps`)، وقناةُ التنبيهات،
وسرُّ رمز التطبيق، وتهشيرُ رموز الاسترداد — **والنسخُ الاحتياطيّة كلُّها**. وأسرارُ Worker تُكتب ولا تُقرأ: لا تعيده Cloudflare.

- **(أ) في الـ Worker وليس عندك**: صدى يعمل، **والنسخُ لا تُفكّ خارج Cloudflare**. ولا تدويرَ بلا القيمة القديمة (M-40 يحتاجها في
  `TOKEN_ENC_KEY_PREV`). فالطريق: (١) `openssl rand -base64 32` ← احفظها في الخزانة **أوّلًا** ← (٢) `npx wrangler secret put TOKEN_ENC_KEY --env staging`
  ← (٣) كلُّ ما شُفّر يصير لا يُقرأ، فأعد ربطَ كلّ حساب (الحسابات ← **أعد الربط**)، وأدخل مفاتيحَ الخدمات وأسرارَ التطبيقات من جديد،
  وقناةَ التنبيهات، وسجّل عاملَك الثاني ورموزَ الاسترداد (§٥). **والقرارُ قرارُك**: يومُ عملٍ الآن بدل فقدٍ لا رجعةَ فيه يومَ الحاجة.
- **(ب) لا في الـ Worker ولا عندك (حُذف السرّ)**: كـ(أ) من الخطوة ٢، ولا خيار. والصفوفُ نفسُها (منشوراتٌ وخططٌ وتاريخ) باقيةٌ مقروءة: ما
  يُفقَد الأعمدةُ المشفّرةُ وحدَها، **والنسخُ التي شُفّرت به لا تُفكّ بعدها**.

**التحقّق**: `curl -s -H 'Authorization: Bearer <ADMIN_TOKEN>' https://sada2.basserh.com/admin/ready` يقول `"keys"` بمعرّفٍ جديد و`"pending":0`؛
و«الحسابات» متّصلة بعد إعادة الربط؛ وأوّلُ نسخةٍ بعده يفتحها التمرينُ بالقيمة الجديدة (`npm run restore`).

**والوقاية**: M-51 الخطوة ١ — نسخةٌ من القيمة في خزانة كلمات المرور، لا في محادثةٍ ولا بريدٍ ولا ملفّ.

## §٥ · المالكُ لا يدخل

1. **فقدتَ مفتاحَ المرور**: صفحةُ الدخول ← رمزُ البريد ← **رمز التطبيق** أو **رموز الاسترداد** (D-317) ← ثمّ **الضبط** ← **الأمان** ←
   سجّل مفتاحًا جديدًا وأزل القديم، **وولّد رموزَ استردادٍ جديدة**.
2. **لا يصل رمزُ البريد**: Email Routing على `basserh.com` (M-31) ← **Destination addresses**: أعنوانُك «Verified»؟ وإلّا فالدخولُ بمفتاح المرور وحدَه.
3. **فقدتَ العواملَ كلَّها** — بابُ الطوارئ بحساب Cloudflare (وهو المحروس بكلمة مرورك وعاملك هناك):
   - خذ علامةً للتراجع: `npx wrangler d1 time-travel info sada-staging --env staging`
   - امحُ عواملَ حسابك وحده: `npx wrangler d1 execute sada-staging --env staging --remote --command "DELETE FROM passkeys WHERE COALESCE(email, '<بريدك>') = '<بريدك>'; DELETE FROM totp WHERE id = 1; DELETE FROM recovery_codes WHERE COALESCE(email, '<بريدك>') = '<بريدك>'"`
   - ادخل برمز البريد ← **سجّل عاملك الثاني** ← مفتاحُ مرورٍ جديد ← رموزُ استردادٍ جديدة.
4. **تشكّ أنّ غيرك دخل**: **الضبط** ← **الأمان** ← **الأجهزة المفتوحة** ← أغلقها كلَّها؛ أو دوّر `ADMIN_TOKEN` (`npx wrangler secret put ADMIN_TOKEN --env staging`)
   فيبطل كلُّ جلسةٍ على كلّ جهاز (D-318).
5. **فقدتَ حسابَ Cloudflare أو GitHub**: استرجاعُه عندهما (رموزُ الاسترداد التي حفظتها لهما، أو دعمُهما) — صدى لا يملك بابًا إليه.

**التحقّق**: تدخل وتفتح «الضبط ← الأمان» فترى عاملًا واحدًا على الأقلّ وثمانيةَ رموز استرداد، و«سجلّ النشاط» يقول الدخولَ بطريقه.
